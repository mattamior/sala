# sala — 已讨论的能力与技术探索（非架构决策）

本文件收集方向和待验证假设，**不是已确定的技术方案、研发排期或 V1 功能承诺**。

## 一、Agent 能力

- 理解模糊创作需求，必要时澄清并维持创作意图、约束及已认可内容。
- 对话驱动的全自动生成与协作式修改；能分析参考图片/视频。
- 自主选择工具，分步生成，诊断失败，根据用户反馈调整策略。
- 根据创作维度选择自由创意或高保真复刻，不将这两种角色硬编码为互斥全局模式。
- 丰富的图像、视频、预设/工作流工具生态，并允许高级用户扩展。

## 二、预演机制

**讨论过的预演形式：**

1. 文字故事梗概、分镜、关键帧、视觉草案。
2. 低保真生成式视频：只供用户检查大致动作/构图，通常不具有真正可编辑三维对象。
3. 真正三维白模/灰模预演：具备几何、姿态、骨骼、摄影机轨迹等结构，可修改比例、空间关系和运动。
4. 参考视频反向分析/重建：尝试提取人物姿态、运动、相机路径、空间布局，构建可调整的简化预演。
5. 利用深度/姿态/轨迹等结构约束下游视频生成，并对比最终输出与预演的一致度。

**关键限制：** “看起来像 3D 白模的视频”不一定包含可编辑三维结构；即使拥有三维控制数据，下游生成结果也不能预设为严格一致。对普通简单风景或氛围镜头，不应强迫走重型白模流程。

## 三、可替换技术候选（仅早期调研）

- Agent：OpenCode、Pi，以及作为能力参考的 Codex / Claude Code。
- LLM：Ollama、MLX 与可配置云端 LLM API；早期试探过 Qwen 等量化模型。
- 图片/视频编排：ComfyUI、MCP、Draw Things、可扩展工作流和预设。
- 渲染后端：本地 Apple GPU / MPS / MLX，或按需使用远程 GPU 与独立图片/视频模型 API。
- 后处理：FFmpeg 等程序化工具。
- 设备背景：维护者有 Mac mini M6、24GB 统一内存、512GB SSD，可用于本地原型，但不限定产品发布平台。

**尚未决定：** 编程语言、应用框架、Agent 运行时、模型提供商接口、打包方式、插件隔离/安全边界、平台支持和视频管线。

## 四、预设可能需要表达的维度（只是研究提案）

- 创作类别：文生图、图生图/局部编辑、图生视频、文生视频、角色一致性、参考复刻、分镜、后期。
- 视觉属性：镜头、灯光、场景、色彩、风格、构图。
- 执行信息：支持模型、预设参数、所依赖工作流、运行条件、输入/输出格式。
- 约束：要保持不变的维度、允许自主的维度、验证依据与结果记录。
