# sala — 产品愿景与边界（讨论基线）

## 一句话定位

**sala 是计划开源、面向广泛用户的 AI 原生视频创作 Agent。** 用户通过自然语言、参考图片和参考视频表达意图；Agent 自主理解、规划和调用工具，用低负担的反馈循环完成视频作品。

核心不是“聊天机器人 + 视频按钮”，也不是传统编辑器加 AI 插件，而是一个以创作意图为中心、由 Agent 主导执行的创作伙伴。

## 产品应具有的体验特征

- **简单接入：** 下载并安装后，用户能用直观方式配置 LLM 的 URL、Key 等连接信息；图片、视频、剪辑等生成服务独立接入，不强制同一个 API 包办一切。
- **强 Agent：** 能规划、调用多种工具、分析参考素材、诊断失败、持续修改作品，而非机械转发提示词到视频模型。
- **高自由度：** 开放模型、工具和预设扩展；不强制所有用户理解 ComfyUI 节点、采样器或专业剪辑术语。
- **视频为重点、图片同样重要：** 图片可为直接作品，也可为角色参考、关键帧、风格参照或视频工作流中间素材。
- **两种创作角色共存：** 当目标模糊，Agent 更像导演，主动提出构思；当要求复刻，Agent 更像精确执行助手，遵守参考与保留边界。这种自主性可以在镜头、动作、人物、场景和风格各维度分别约束。
- **先达成意图共识：** 对关键含混要求倾向先沟通、先给低成本可视化方案，不以盲目试错替代理解。
- **作品优先：** 图片、片段、分镜、版本与参考对照可成为人与 Agent 的沟通语境，但不应把普通用户推向传统专业编辑工作流。

## 非目标和注意事项

- 当前**不是**为维护者的 Mac mini 量身设计的一次性部署脚本。
- 当前**不是**要求只配置一组 LLM API，就不需其他媒体生成资源。
- 当前**不是**先制造一套繁琐的可视化时间线编辑器。
- 当前**不是**已承诺自动重建任意视频的真实、精确 3D 场景。
- 先前提出的 OpenCode / Pi + Ollama + ComfyUI / MCP 等是探索阶段建议，**用户尚未确定底座**。
- 普通用户的完整首次上手旅程是重要的后续产品问题，但用户已要求先专注 Agent 核心能力，不在当前阶段过早写定。

## 成功的概念性判断标准（待量化）

1. 用户以很少的专业术语表达需求，Agent 能正确理解并提出必要澄清。
2. 精确复刻任务能明确区分应保留/应改变的维度。
3. 局部修改不会悄悄破坏用户认可的其他部分；若无法满足边界，需显式告知。
4. 用户可通过选择时间段、参考对照、圈选或多个候选等轻量操作指认问题。
5. 工具与模型可自由替换，产品的创作约束与记录不会依赖单一厂商。
6. 失败重试有诊断与依据，而不是无限随机重生成。

以上是产品目标，不是已经通过测试的性能承诺。
