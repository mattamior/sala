# sala — 未决问题与研究顺序

本文件用于明确**哪些还没有决定**，避免把聊天中的建议误读为维护者授权的方案。

## Agent 核心

1. Agent 应具备哪些最低能力才能称为“强 Agent”？工具调用、规划深度、持久任务、失败诊断和评估如何分阶段验证？
2. 对高精度参考复刻，怎样量化镜头、动作、身份、空间布局、时序和非目标区域保真度？
3. 如何表示和持续更新用户的“创作共识”：目标、硬约束、软目标、确认状态、被否定方案？
4. 什么程度的不确定性触发澄清？如何避免连续追问造成摩擦？
5. 如何在不提供完整专业编辑器的情况下，用时间段、指向、对照、候选与白模预演传递上下文？

## 媒体生成

6. 白模预演是生成式草稿、真实 3D、还是多级混合机制？如何确定实际可靠性？
7. 能否从真实参考视频稳健提取姿态、轨迹、摄影机和三维关系？哪些输入会不可恢复或产生歧义？
8. 下游视频模型对结构约束的遵从程度如何实测？无法精确复刻时应如何向用户表述？
9. 本地、远程 GPU、第三方图片/视频 API 的成本、自由度和适配策略如何设计？

## 产品和工程

10. Agent 底座是否应采用现成框架、可扩展运行时，还是自主开发差异化部分？
11. 如何做到“下载 + 简单配置”与多媒体引擎/模型/预设依赖管理兼顾？
12. 哪些高级扩展能力在不牺牲默认易用性的前提下应公开？
13. 哪些操作需要授权、成本上限或安全隔离？如何避免 Agent 无限制下载、执行脚本、消耗付费资源？
14. 首发支持哪些操作系统？维护者 Mac mini 只是一个初始测试环境。
15. 最终 UI 的作品画布、对话以及抓手之间如何布局？用户已表示应先理解/建设强 Agent，暂缓完整首轮用户旅程。
16. 何时决定 GitHub 开源许可证、品牌与域名、社区治理？

## 已经明确不是开放式争论的问题

- 名称作为当前代号：`sala`。
- 目标是可分发、易上手且高度自由的开源 Agent 产品，不是个人 Mac 工作站。
- 用户可通过参考图与参考视频驱动高精度复刻。
- 自主性应随任务和维度变化。
- 关键意图不明时，优先低负担澄清再正式执行。
- 可视化抓手服务于沟通，而不是优先复制传统剪辑软件。
