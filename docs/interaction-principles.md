# sala — Agent 交互原则与场景

## 原则 1：Agent 执行，用户表达意图与做决策

用户负责描述目标、提供参考、评价结果、指出问题；Agent 负责内部分析、拆解任务、选工具、执行与迭代。可视化对象是双方沟通的**抓手**，不是要求用户直接编辑底层工作流。

## 原则 2：先澄清关键歧义

对意思不清、会改变创作方向的反馈，倾向先通过一个简短问题、参考对比或可视化候选达成共识，再正式生成。用户已明确选择这一原则，而不是默认“先随机生成再看”。对于已经明确的内容不反复询问。

## 原则 3：自主性是逐维度的

一个请求可以同时规定：镜头运动严格复刻、人物动作严格复刻、主角换成参考图片中的角色、场景改成未来东京、灯光色彩由 Agent 决定。不是简单的“复刻模式 / 创意模式”二选一。

## 原则 4：视觉抓手的三种交互

- **指认：** 选中某个镜头、时间段、画面区域、对象；把对应范围一起传给 Agent。
- **对比：** 原片/参考片与生成片按镜头和时间对照，标出不符合预期的差别。
- **决策：** 从候选构图、光照、镜头或预演中选方向，再通过自然语言补充约束。

## 讨论案例：选中 5–8 秒修改转身

用户输入：

> “人物转身太慢了，参考视频的动作更干脆。其他镜头保持不变。”

### Agent 应建立的创作意图

- **指向：** 当前视频 5–8 秒中的人物转身，与参考视频中对应动作比较。
- **修改目标：** 提高动作的果断感，可能涉及起转时机、旋转速度、头肩躯干协调、停止时机；不直接把“更干脆”简化为“整体视频加速”。
- **硬约束：** 其他镜头保持不变；当前镜头里未要求改变的身份、服装、背景、光线、运镜应尽可能维持一致。
- **边界影响：** 5–8 秒改变动作后，检查 5 秒/8 秒交界处的姿态、节奏、视觉连续性；不能无许可偷偷修改相邻镜头。
- **含糊时先澄清：** 如果参考对应镜头、完成时间或不能变动的部分不明确，用对比抓手确认而非擅自推断。

### Agent 的内部工作与验证目标

1. 分析原片与参考的动作差异，不仅是速度，也可能是起始延迟、停顿及运动轨迹。
2. 判断最小必要变更；能修局部就不要随意重做整条视频。
3. 允许低保真预演或动作草案先获确认，再进行高成本成片。
4. 分开核验：**目标动作达成度**、**非目标内容保真度**、**局部与整体连续性**。
5. 若无法真正保持其他镜头/内容不变，必须向用户说明；不能把“修改命令执行成功”等同于“创作效果已达到”。
6. 保存创作共识及用户接受/否定的修改方向；用户说“再快一点”是原意图的持续迭代，不是没有历史的新任务。

## 参考复刻范例

输入：一段参考视频 + 一张新角色参考图。

要求：替换原视频主角，保留镜头移动、人物动作、构图与节奏；特定场景和美术风格允许按用户要求变化。Agent 可以通过最少的提示确认“是否保留原有美术风格”，而不是要求用户填写专业参数。

## 待验证的交互假设

- “作品作为共同上下文”可能比“聊天窗口为唯一中心”更高效，但还没有正式确定 UI 形态。
- 白模预演能够提高时空意图的表达准确度，但不能默认视频生成模型会百分之百遵循白模。
- 自动质检可发现一些技术与连续性错误，但不能替代用户的主观审美判断。
