# Decisions — sala

本文件只记录维护者已明确表达或明确同意的方向。未确立的建议和示例应参见 `docs/open-questions.md`。

## D-001 — 项目代号 sala（暂定）
- **状态：已采用为项目代号；品牌最终核验待办。**
- 小写 `sala`；仓库名也是 `sala`。名称来源于维护者的直觉，不基于特定语源或功能缩写。
- 命名审美偏好：两个音节、自然、简短、轻盈、国际化；字母数量不限，不必技术化或有明确含义。
- 不应误写为商标注册完成、域名取得或永久品牌定案。

## D-002 — 产品是可分发的开源创作 Agent，而非个人 Mac 工作站
- **状态：产品方向确定。**
- 目标：用户下载产品、配置所需 LLM 接入信息（如 URL / Key）及生成后端后，即可用自然语言创作；强调好上手和高自由度。
- **更正的重要误解：** 没有要求一个 LLM API 同时承担文本对话、图像和视频生成；服务可以分离接入。
- 应提供丰富的图片/视频工具与预设，底层具体选型未定。

## D-003 — 自动创作与协作迭代并存
- **状态：交互原则确定。**
- 用户选择此前讨论的 C：既可一句话创作，也可随时介入，Agent 独立完成内部分析、工具调用和修改。
- 支持用户提供参考图、参考视频，进行高精度的再创作/复刻。

## D-004 — 自主性由创作意图决定，且可分维度
- **状态：交互原则确定。**
- 用户选择此前讨论的 C：精确复刻时严格参照；模糊创意时主动构思。
- 对镜头、动作、人物、场景、灯光等维度可分别遵从/自主，不应简单只有一个全局模式开关。

## D-005 — 可视化“沟通抓手”，不是先做专业编辑器
- **状态：交互原则确定。**
- Agent 自主分析与执行，用户通过对话表达反馈；使用时间段选择、区域指认、参考对照、方案选择等抓手降低沟通歧义。
- 不以让用户手动编辑关键帧、节点工作流或传统剪辑时间线为中心。

## D-006 — 关键意图先澄清，再正式执行
- **状态：用户明确选择 B。**
- 当 Agent 对关键创作意图把握不足时，倾向先通过简短问题/候选方案/预演澄清，而不是先大量生成再让用户判断。
- 不是要求已明确的每一个步骤都机械地重复确认。

## D-007 — 白模及参考反向重建是重要研究方向
- **状态：认可潜力，未确定 V1 范围和技术方案。**
- 用户认为先用白模确定布局、比例、轨迹再最终生成是值得探索的中短期优化；进一步从参考视频推断并重建可编辑三维预演也被认为有潜力。
- 这些尚未经过技术验证，不得写为已实现或承诺必做。

## D-008 — 当前不急于落地技术方案及首轮 UX
- **状态：当前工作优先级约束。**
- 用户要求通过多轮讨论理解真实需求，而不是立即执行先前提出的个人部署和框架方案。
- 详细“第一次打开产品到完成第一条视频”的体验设计，不是当前优先级；优先明确并发展强 Agent 的能力。

## D-009 — 先设计创作共识，再选 Agent 技术底座
- **状态：当前讨论优先级已获维护者同意（2026-10-18）。**
- 维护者同意优先明确「创作共识」的表示与跨轮继承，重点研究目标、修改与保留约束、可自主维度、作用范围及验证依据。
- 这一决定**不等于**批准 `docs/creative-consensus.md` 中具体的数据字段、默认规则、协议、UI、测试方案或技术实现；所有设计细节仍待逐项评审。
